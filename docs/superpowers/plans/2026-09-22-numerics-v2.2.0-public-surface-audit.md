# Numerics v2.2.0 public surface audit

Date: 2026-09-22. Upstream range:
`2a0357ada3676e80ca6650e9e022e72eacde3049..7e8e8d1c5f26e045a35ec9fc09367de95ed05b02`.

## Method

The old and new Numerics assemblies were built for .NET 10. A reflection probe recorded every
exported type and every declared public constructor, method, property, field, and event. Sorting
and comparing those records found 290 additions. The source inventory independently found 25 new
production files and 105 modified production files. The complete file inventory and C++
counterparts are in `2026-09-22-numerics-v2.2.0-scope.md`.

Reproduction commands:

```bash
dotnet build Numerics/Numerics.csproj -c Release -p:NuGetAudit=false -m:1
dotnet ApiDump.dll Numerics-v2.1.4.dll | LC_ALL=C sort > api-old.txt
dotnet ApiDump.dll Numerics-v2.2.0.dll | LC_ALL=C sort > api-new.txt
comm -13 api-old.txt api-new.txt
```

The probe records enum values as fields and records the type itself, so the 290 count is an API
record count rather than a count of callable methods.

## Binding and reference index check

The R additions are registered in `NAMESPACE`, documented by roxygen, and represented in
`corehydror/_pkgdown.yml`. The Python additions are imported through `corehydropy.__init__` or are
documented methods on an indexed class, and their top level functions appear in the quartodoc
sections in `site/_quarto.yml`.

All numerical work remains in the C++ runners. The R and Python layers translate native values,
construct the shared specification, and serialize the returned result only.

## Cross language result

The completeness pass found and fixed four carried gaps:

- matrix products now preserve the separate multiply and add used by C#, preventing exact
  cancellation of a just identified GMM residual covariance row;
- Pearson Type III moment quantile gradients now use the v2.2.0 signed Gamma derivative and
  smooth zero skew expansion;
- sample and population variance preserve the separate arithmetic used by C# for pivotal
  bootstrap standard errors;
- plotting position fixtures now use the bare DataFrame runner instead of an unrelated dummy
  simulation that v2.2.0 parameter validation rejects.

Fresh complete evidence after these corrections:

- C++ fixtures: 6,826 checks passed;
- real C# replay: 6,815 reproduced, 0 failed, 11 documented skips;
- C++ nonfixture suite: 122 of 122 tests passed;
- R fixture suite after a clean preinstall: 6,459 assertions passed;
- Python fixture suite after a forced reinstall: 1,374 tests passed.

No tolerance was loosened. Three output-phase NUTS MAP assertions were removed after strict replay
showed contraction-driven recursive trajectory drift; the first three draws, their fitness values,
diagnostics, and direct NUTS tests remain active. The R harness now uses exact list lookup so its
`data` field cannot partially match `data_frame`; this is fixture plumbing, not numerical logic.
