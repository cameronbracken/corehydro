# Numerics v2.2.0 upstream sync implementation plan

Date: 2026-09-22. Status: proposed; implementation has not started.

## Goal

Restore corehydro parity with USACE-RMC Numerics v2.2.0 at
`7e8e8d1c5f26e045a35ec9fc09367de95ed05b02`, starting from the current Numerics v2.1.4 pin at
`2a0357ada3676e80ca6650e9e022e72eacde3049`. Adopt shipped numerical behavior, add the new public
surface that belongs in corehydro, re-pin affected fixtures against the real C# library, and retain
an explicit record of every deliberate severance.

RMC.BestFit remains pinned at v2.0.0 (`c2e6192`). Its current `main` branch is one commit ahead,
but that commit only deletes `docs/PROGRESS.md`. No BestFit source port is part of this sync.

The release changes numerical results and validation behavior. The main affected areas are
distribution tails and fitting constraints, mixture and competing-risk evaluation, singular
multivariate normals, MCMC diagnostics and NUTS adaptation, BFGS and Powell convergence, matrix
regularization, bootstrap uncertainty, weighted statistics, interpolation, quasi-random sampling,
and the dynamic network algorithms.

The release also adds public APIs: weighted statistics and global sensitivity, adaptive 2-D
Gauss-Kronrod integration, scrambled Sobol points for Vegas, conditional copula functions and an
Independence copula, composable univariate functions, sided extrapolation, empirical convolution,
singular-covariance multivariate normal support, and expanded shortest-path routing.

## Authority and constraints

- Work in a dedicated worktree on branch `upstream-sync-numerics-v2.2.0`. Keep `main` as the
  integration lane. Do not push, merge, tag, publish, or remove the worktree without separate
  authorization.
- The source at tag `v2.2.0` is normative. Commit subjects and intermediate revisions only locate
  relevant files. Read the complete shipped file and its shipped tests before changing C++.
- Preserve structural mirroring. Every changed or added C++ port carries
  `// ported from: <C# path> @ 7e8e8d1`.
- Keep the C++17 core self-contained. Do not add Eigen or another compiled dependency.
- Oracle values live only in `fixtures/*.json`. Do not hardcode C# expected values in C++, R, or
  Python tests.
- Do not relax fixture tolerances or add an `oracle_skip` to make a changed result pass. Diagnose
  the difference, then either reproduce shipped C# behavior or record a justified severance.
- Preserve seeded cross-language equality where the shipped algorithm permits it. If a changed
  algorithm is sensitive to floating-point reassociation, establish deterministic structural
  assertions and document the evidence rather than claiming exact equality.
- A new C# public API must have one recorded disposition: exposed in R and Python, used internally
  by an existing surface, or deliberately severed with a reason and a direct C++ test where useful.
- Continue to sever live downloads, C# XML persistence, UI/reporting, and parallel-only helpers
  unless shipped numerical behavior requires them. Reassess each changed file rather than copying
  the old verdict without inspection.
- Initial known non-porting dispositions are `TimeSeriesDownload.cs` (live I/O),
  `SafeProgressReporter.cs` (C# progress infrastructure), and `Numerics.csproj` (build metadata).
  Confirm these verdicts against the shipped hunks during Task 0.
- Use `R CMD INSTALL --preclean corehydror` after every class-layout change.
- Run `cpp11::cpp_register("corehydror")` only after changing `corehydror/src/*.cpp`.
- Use one implementation commit and one review-fix commit at most for each task. Commit subjects
  use `<type>: <description>`, commits are signed, and commits have no `Co-Authored-By` trailer.

## Task order

The order follows numerical dependencies. Shared math, linear algebra, integration, and optimizers
land before distributions and samplers that consume them. A task is complete only when its changed
C# files have dispositions, its affected APIs have tests, all four relevant runners agree, and an
independent review has no unresolved high-severity finding.

## Review contract for each task

The reviewer receives the task requirements, base and head commits, changed-file list, fixture
changes, and complete focused/full gate outputs. The reviewer checks:

- shipped C# semantics rather than commit-message summaries;
- line-for-line structural fidelity where practical;
- coverage of changed behavior, boundaries, validation, and exceptions;
- absence of numerical logic in R or Python glue;
